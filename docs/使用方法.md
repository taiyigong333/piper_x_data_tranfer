# Piper-X 数据转换为 StreamPI 格式

## 环境

```bash
cd /home/cv/gcj/project/data_transfer/to_streampi/code
UV_CACHE_DIR=/tmp/uv-cache uv sync
```

## 转换本次指定批次

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run python -m piperx_to_streampi.convert \
  --input /home/cv/gcj/data_collect/data/rotating_red_square_blue_plate /home/cv/gcj/data_collect/data/rotating_red_square \
  --batches 2 3 4 5 \
  --output /home/cv/gcj/project/data_transfer/to_streampi/after_transfer/piperx_rotating_red_square \
  --language "grab the rotating red square"

```

仅转换 `batch_*/**/forward/trajectory.hdf5`，反向数据不会进入训练集。输出目录非空时需显式添加 `--overwrite`。默认语言为本次任务指令，也可通过 `--language` 修改。

## 输出与对齐

每个 episode 输出一个 Parquet 文件和三路 MP4。图片按比例缩放并补黑边至 `224x224`；采集输入为固定相机和右腕相机，分别映射为 `cam_high`、`cam_left_wrist`。StreamPI 固定三路视觉输入，未采集的 `cam_right_wrist` 用全黑帧占位。Parquet 中 `observation.state` 与 `action` 均为 StreamPI AgileX/PiperX 约定的 14 维 `[左臂6关节, 左夹爪, 右臂6关节, 右夹爪]` 向量。本次单臂采集写入左臂槽位，右臂槽位为零填充。原始高频状态依相机时间戳插值到 30Hz；action 是下一采样时刻的 state，最后一帧延续自身。

## 最小验证

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run python -m compileall -q piperx_to_streampi
```

检查输出 `meta/info.json` 的 fps 为 30、图像 feature shape 为 `[224,224,3]`，episode 数与输入目录的 forward HDF5 数量一致。
