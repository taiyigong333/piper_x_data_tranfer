# 使用方法

## 目录与环境

在 `/home/cv/gcj/project/data_transfer/to_tempo/code` 下操作。
Git 仓库、Python 包、uv.lock 和 `.venv` 均在此目录；数据输出位于相邻 `after_transfer`。

```bash
cd /home/cv/gcj/project/data_transfer/to_tempo/code
uv sync --locked
uv run piperx-to-tempo --audit-only
```

Python 固定 3.11；转换仅需 CPU。默认 12 个进程并行处理 episode，每个进程的视频编码使用一个线程。
无需为数据转换安装 TEMPO 的 torch/JAX/SAM2 训练依赖。
若系统限制默认 uv 缓存，可加 `UV_CACHE_DIR=/tmp/tempo-uv-cache`；本次执行使用此缓存。

## 本次输入与输出

`config/convert.json` 显式选择：

| 数据根目录（省略 `/home/cv/gcj/data_collect/data/`） | batches |
| --- | --- |
| rotating_red_square_blue_plate | 2、3、4 |
| rotating_red_square | 5 |

只查找 `batch_N/*/forward/trajectory.hdf5` 及旧式 `*_trajectory.hdf5`。
不扫描 reverse、其他 batch 或隐藏临时目录。指定 batch 缺失、空白名单、重复输入均报错。
内部 batch_tag 存在历史误标，筛选依据是目录；内部原值另存来源清单。
不额外按 quality 筛选，符合输入白名单的正向轨迹全部转换。

本次合并为一个数据集，episode 连续编号，便于训练和 SAM2 缓存索引：

```text
../after_transfer/piperx_rotating_red_square/
├── data/chunk-000/episode_NNNNNN.parquet
├── videos/chunk-000/observation.images.head/episode_NNNNNN.mp4
├── videos/chunk-000/observation.images.left_wrist/episode_NNNNNN.mp4
└── meta/
    ├── info.json / tasks.jsonl / episodes.jsonl
    ├── stats.json / episodes_stats.jsonl
    ├── conversion.json          # 生效参数、动作定义、相机映射
    ├── source_episodes.jsonl     # 每条轨迹原路径、SHA256、原语言、时间对齐记录
    └── validation.json          # 全量验证结果
```

四个批次共 393 条、44,398 帧、786 个 H.264 视频，输出频率统一为 30Hz。
batch_2/3/4/5 分别对应 episode 范围 0–103、104–190、191–288、289–392。

## 执行转换与修改 language

```bash
# 使用配置默认的全部指定批次；已存在的输出将被拒绝覆盖
uv run piperx-to-tempo

# 修改 language 和输出位置，不改动原采集文件
uv run piperx-to-tempo \
  --language "grab the rotating red square" \
  --output ../after_transfer/piperx_new_run \
  --workers 12

# 仅审计真实时间戳和采样覆盖，不写输出数据
uv run piperx-to-tempo --audit-only
```

也可复制 `config/convert.json` 后修改 `inputs[].batches`、`language`、`output`，用 `--config` 指定。
相对 output 以配置文件上一级目录为基准；CLI `--output` 以当前工作目录为基准。
配置中的输入 root 推荐使用绝对路径。当前为已核对的 TEMPO 固定 30Hz 和 224×224，其他值会拒绝。
支持图像匹配误差与机器人采样间隙阈值配置，默认均为 100ms。

转换先全量审计，再写 `<output>.partial`；全部文件成功写入后才改为正式输出目录。
失败时保留 partial 便于定位；不会自动覆盖或删除已有输出，不支持断点续跑。
不把源文件、转换数据、.venv、日志提交到 Git。

## 验证

```bash
uv run tempo-validate ../after_transfer/piperx_rotating_red_square --workers 12
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 uv run pytest -q
uv run ruff check piperx_to_tempo_vla tests
uv run python -m compileall -q piperx_to_tempo_vla
```

验证器核对所有指定来源与 SHA256、状态插值、下一帧动作、全局/帧/任务索引、语言、
全部视频解码帧数/224×224/FPS/PTS，成功后写入 `meta/validation.json`。
关闭 pytest 自动插件是为了避免本机 ROS 的 Python 3.10 插件进入本项目 Python 3.11 环境。

`stats.json` 是原始数据统计，不能替代训练前官方 `compute_norm_stats.py` 生成的增量动作归一化统计。
训练步骤见 [TEMPO 训练说明](TEMPO训练参数与数据表示.md)。

## 采集配置存档

- `config/d405_d435i_2026_10_7.json`：用户指定的相机参数原样副本。
- `config/grab_rotating_red_square.yaml`：用户指定的任务参数原样副本。
- `config/grab_rotating_red_square_into_blue_plate.yaml`：由 HDF5 source_config 发现的早期任务配置原样副本。

配置副本是当前采集项目文件，不能保证是所有历史 batch 当时版本；HDF5 的原始元数据仍是追溯依据。
