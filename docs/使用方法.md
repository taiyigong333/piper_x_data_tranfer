# Piper-X 数据转 OpenPI

## 输入与输出

输入为 `/home/cv/gcj/data_collect/data/rotating_red_square_blue_plate` 下的采集批次。转换器仅读取 `forward` 子目录中的 HDF5 轨迹，默认处理 `batch_2`、`batch_3`、`batch_4`，并输出 LeRobot v2.1 数据集，供 OpenPI 的 LeRobot loader 使用。

每帧包含 `camera_front`、`camera_wrist_right` 两路 RGB 图像，图像保持宽高比缩放并用黑边补到 `224x224`。状态由末端位姿 `[x, y, z, rx, ry, rz]` 与夹爪位置组成 7 维向量。采集器的 `_align` 状态若与相机帧一一对应则直接使用；否则根据高频状态时间戳插值到相机帧时间。输出视频和状态时间轴均为 30Hz。动作记录下一帧状态，episode 最后一帧动作重复末帧状态。

## 环境与转换

```bash
cd /home/cv/gcj/project/data_transfer/to_pi/code
UV_CACHE_DIR=/tmp/uv-cache uv sync
UV_CACHE_DIR=/tmp/uv-cache uv run python -m piperx_to_openpi_vla.convert \
  --input /home/cv/gcj/data_collect/data/rotating_red_square_blue_plate \
  --output /home/cv/gcj/project/data_transfer/to_pi/code/output/piperx_rotating_red_square \
  --batches 2 3 4
```

如果需要统一修改转换后数据集的语言指令，可增加 `--language-instruction`。该值会写入 `meta/tasks.jsonl` 和 `meta/episodes.jsonl`，并用于 Parquet 的 `task_index`，OpenPI 训练时读取到的每个 episode 指令都会使用它：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run python -m piperx_to_openpi_vla.convert \
  --input /home/cv/gcj/data_collect/data/rotating_red_square_blue_plate/batch_4 \
  --output /home/cv/gcj/project/data_transfer/to_pi/code/output/batch_4 \
  --batches 4 \
  --language-instruction "grab the rotating red square and put it into the blue plate" \
  --overwrite
```

不提供该参数时，转换器沿用每条源 HDF5 中的 `metadata/language_instruction`。空字符串会直接报错，避免生成无法用于训练的任务描述。

再次写入非空输出目录時，需明確加 `--overwrite`。只转换单个 batch 时，将 `--input` 指向该 batch 目录并相应设置 `--batches 2` 等参数。默认仅选取指定批次，批次中每个正式 `forward/trajectory.hdf5` 都会转换；反向目录、zip 文件和临时 staging 目录不会参与。

输出结构包含 `data/` 中的 Parquet、`videos/` 中的 30Hz MP4，以及 `meta/` 中的 `info.json`、`stats.json`、`tasks.jsonl` 和 episode 清单。输出数据应在训练配置中映射为 OpenPI 所需的 image、wrist image、state 和 actions 字段；训练使用 30Hz 数据集 fps。模型侧的状态/动作归一化统计仍需按 OpenPI 训练配置计算或指定。

## 采集配置

- `config/d405_d435i_2026_10_7.json`：采集时使用的相机配置副本。
- `config/grab_rotating_red_square.yaml`：采集时使用的任务配置副本。

这些配置只用于追溯采集参数，不会在离线转换中改变源数据。

## 最小检查

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run pytest -q
```

转换后检查 `meta/info.json` 中 `fps` 为 30、图像 feature shape 为 `[224, 224, 3]`，并确认 episodes 数量与选定批次中 forward HDF5 文件数量一致。
