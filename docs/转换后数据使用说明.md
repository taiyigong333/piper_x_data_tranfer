```text

├── videos/chunk-000/
│   ├── observation.images.cam_high/episode_******.mp4
```

`data/` 保存每帧的状态、动作和索引；`videos/` 保存对应 episode 的视频；`meta/` 保存 LeRobot v2.1 数据集描述、归一化统计和任务清单。

## 3. StreamPI 读取映射

训练配置中的数据仓库路径应指向上面的数据集目录。字段映射如下：

| 转换后字段 | StreamPI 含义 |
| --- | --- |
| `observation.images.cam_high` | 固定前视相机 |
| `observation.images.cam_left_wrist` | 采集时的腕部相机，映射为左腕输入 |
| `observation.images.cam_right_wrist` | 当前未采集，使用全黑占位帧 |
| `observation.state` | 当前 14 维关节状态 |
| `action` | 下一时刻的 14 维目标关节状态 |
| `task_index` / `meta/tasks.jsonl` | 语言任务索引和指令 |

14 维状态顺序与 StreamPI 的 AgileX/PiperX policy 一致：

```text
[left_joint_1 ... left_joint_6, left_gripper,
 right_joint_1 ... right_joint_6, right_gripper]
```

本次是单臂采集，因此真实关节和夹爪写入左臂 7 维，右臂 7 维为零。关节值沿用采集器的弧度单位，夹爪值沿用采集器输出。不要将该数据集当作末端位姿数据读取。

## 4. 训练前检查

在 StreamPI 训练配置中确认：

1. `repo_id` 或数据路径指向 `piperx_rotating_red_square`。
2. repack transform 将 `action` 映射为动作字段，将 `observation.state` 映射为状态字段。
3. AgileX/PiperX policy 的动作维度为 14，并使用正确的关节顺序。
4. 三路图片名称与上表一致；右腕黑帧应按缺失视角处理。
5. 数据 fps 按 30 Hz 解释，历史帧间隔和 action horizon 不要按原始 60 Hz 状态频率解释。
6. 使用本数据集重新计算或指定 `stats.json` 对应的 normalization statistics。

训练参数如 batch size、learning rate、action horizon、时序上下文长度和训练步数由 StreamPI 的具体配置决定，参见 `StreamPI训练数据与参数说明.md`。

## 6. 重新转换

转换代码和 uv 项目位于：

```text
/home/cv/gcj/project/data_transfer/to_streampi/code
```

网络正常时初始化环境：

```bash
cd /home/cv/gcj/project/data_transfer/to_streampi/code
UV_CACHE_DIR=/tmp/uv-cache uv sync
```

重新指定批次或语言指令：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run python -m piperx_to_streampi.convert \
  --input /home/cv/gcj/data_collect/data/rotating_red_square_blue_plate \
          /home/cv/gcj/data_collect/data/rotating_red_square \
  --batches 2 3 4 5 \
  --output /path/to/output_dataset \
  --language "grab the rotating red square" \
  --overwrite
```

`--overwrite` 会删除并重新生成已有输出目录，使用前确认输出路径正确。转换器只读取 `forward/trajectory.hdf5`，不会自动读取反向数据。
